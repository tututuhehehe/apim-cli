## A 组 · TODO-1：OAuth 凭据按厂商存之后，按 `x` 导入 Codex 官方路该写哪一份

### A01 单槽约束：接受还是本轮就做「多登录位」
- 影响：决定后面全部 A 组条目的形态。
- 选项：a) 接受单槽；b) 本轮做多登录位（= apim 管多个 `CODEX_HOME`）。
- **我的答复：a**（⏳ 待确认）。`codex --profile` 换的是 config 不是 auth，Codex 自己在一个 `CODEX_HOME` 下也只有一份登录位；「管理多个 codex 安装根」是另一个功能，用户可见成本远大于收益。

### A02 凭据的键：`provider id` 还是 `provider.alias`
- 影响：能否同时保有同一厂商的多个账号；AUTH 行 / ★ 对账 / 导入面板是否要多一层选择。
- 选项：a) 按 provider id（`openai-oauth.<id>.json`）；b) 按 alias（与密钥对称，多一层 UI）。
- **我的答复：a**（✅）。官方路是「这个厂商的官方账号通道」，不是某把 key 的属性；alias 维度要在三处各加一层选择，而当前没有真实的多账号需求。将来真需要，再加 `oauth_id` 维度，不阻塞现在。

### A03 OAuth 能力怎么声明
- 选项：a) recipe 加 `oauth: openai_codex`（serde default 无；编辑表单只读，与 `kind` 同口径）；b) 继续硬编码 id。
- **我的答复：a**（✅）。一次替掉 6 处 `== Some("openai")` 重复门，且不往表单加预设类型（与约定 2 同旨）。

### A04 核心：按 `x` 写谁的凭据
- 影响：`x` 的语义、AUTH 行分布、导入后提示语；动 `app::open_import` / `clients/codex/official` / `ui::{keys,balance}` / README 导入章节。
- 选项：a) 写**当前 AUTH 行所在厂商**那份（覆盖前照旧备份，代价靠文案承担）；b) 固定写内置 `openai`；c) 导入时让用户选。
- **我的答复：a**（⏳ 待确认，这是最该你复核的一条）。理由：不引入新全局状态，`x` 保持「导入我眼前这一份」；选 (c) 会让每次导入都多一步，而单槽下答案永远相同；(b) 会让「按厂商存」对导入毫无意义。

### A05 覆盖之后 A 的凭据留不留
- 选项：a) 保留、不删不问；b) 一并删；c) 弹窗问。
- **我的答复：a**（✅）。A 的凭据仍服务 A 的额度查询，切回只差一次 `x`；不可逆操作的默认应当是保留。

### A06 旧单文件怎么迁
- 选项：a) 读时迁移（发现旧文件且 id 是 `openai` → rename，host-id 同）；b) 启动时一次性迁移；c) 不迁。
- **我的答复：a**（✅）。映射唯一无歧义，且天然覆盖「升级后没开 TUI 直接用 CLI」；用测试钉住「旧文件不在了、内容逐字节相同、权限仍 600」。

### A07 本轮范围：回写与竞态做不做
- 选项：a) 回写不做、`§3.9` 竞态本轮一起修；b) 都做；c) 都不做。
- **我的答复：a**（⏳ 待确认）。按厂商存之后 `save` 的归属逻辑本来就要重写，顺手做 CAS 最省；回写（`TODO-2`）要认 ownership、要碰刷新节奏，单独一轮。执行方式：把 `TODO-12` 的 CAS 部分作为一张 ticket 挂到本次 spec 下（不是整条 TODO-12 都做）。

### A08 多厂商 AUTH 状态：单槽还是 `HashMap`
- 选项：a) 跟着当前厂商走（切厂商重查）；b) `HashMap<String, _>`。
- **我的答复：a**（✅，可由 A01+A04 推出）。单槽下同一时刻只有一份在起作用，`HashMap` 是过度设计。

### A09 ★ 与「Codex：…」的对账口径
- 选项：a) 回读 `auth.json` 的 **refresh token** 与 apim 各厂商凭据对账，显示「Codex：官方 OAuth（provider A）」，对不上显示「非 apim 写入的外部登录」；b) 只显示「官方 OAuth」。
- **我的答复：a**（✅）。这是 A04 那个代价的**可见性**：不点名是谁，用户就不知道「B 是否真顶掉了 A」。注意只比 refresh token（access token 会轮换）。

### A10 「内置 `openai` 不可复制」这条闸要不要放开
- 选项：a) 放开 + 同轮补上单槽提示；b) 保留闸。
- **我的答复：a**（⏳ 待确认）。闸当初存在的理由（凭据全局一份）被这次改造消掉了，继续拦就成了「没有理由的限制」。**但这一条会外溢**：`recipe/dup.rs::ensure_copyable`、`src/cli/tests.rs::provider_copy_refuses_the_builtin_openai`、`README.md` / `README.zh-CN.md` 的说明（约定 7 要求双语同步）、AGENTS 约定 11 里那段——同一轮全部要改。

### A11 导入前要不要加确认
- 选项：a) 不加通用确认；未登录时按 `x` 提示「先按 `o`」；b) AUTH 行加确认弹窗；c) 未登录时直接开登录。
- **我的答复：a + 一条补充**（✅）。与你现在 `x` 全程无确认一致；但成功后**必须点名**「已从 A 顶掉」，未登录时给「先按 `o` 登录」而不是静默。

### A12 CLI 形状
- 选项：a) 位置参数 `apim auth <provider> login|status|logout|import-codex`，缺省 `openai` 兼容旧命令；b) `--provider <id>`。
- **我的答复：a**（✅）。与 `provider` / `key` 子命令风格一致，旧命令靠缺省值继续可用。

### A13 导入面板要不要「目标厂商」这层信息
- 选项：a) 不加；b) 加一行只读「目标厂商」；c) 加一步可改。
- **我的答复：a**（✅）。在哪个厂商页按 `x` 就是哪个厂商；加只读信息反而暗示「可以改目标」。厂商名放进成功报告的提示里就够了。
