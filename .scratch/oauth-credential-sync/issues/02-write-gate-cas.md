# 02: 写入闸 —— 登录与在途探针不再互相覆盖

Status: ready-for-agent
Blocked by: 01

**What to build:** 结束 `TODO-12` 的用户可见故障：登录成功后磁盘上**一定**留的是刚登进去的那份凭据，哪怕是有一个在途的额度探针（它 `load` 在登录之前、`save` 在登录之后）。做法是把凭据文件分成两类写者 —— 登录是权威写（无条件），一切从已加载快照派生的写（刷新）带上「我读到的那份」并**在写锁内重读磁盘**比对身份，不一致就跳过、不写。用户可见结果：底栏说「已连接」不再是谎话；`apim auth openai logout` 之后在途刷新也不会把凭据复活。

- [ ] 新增受限写：带 baseline（写者开始时读到的那份凭据），在既有写锁内重读磁盘、比对身份，一致才写，并返回「写了 / 跳过了」
- [ ] 身份 = `client_id` + `refresh_token`；另两种边界同样跳过：baseline 是「本来没有」而现在有、baseline 是「有」而现在没有（被注销删掉）
- [ ] 既有 `save` 的语义与签名不变，登录继续无条件写（它是权威写）
- [ ] **写完把 baseline 推进成刚写进去的那份**：`refresh` 一次调用里的第二次写盘（补 account id）拿第一次的结果当 baseline，否则 account id 永远补不上
- [ ] 刷新被跳过时**不报错**：`fetch_usage` 重读磁盘后整体重试**一次**（上界写死为 1 次重试），二次跳过按「这一轮没有读数」处理、不弹错误
- [ ] 重读磁盘发生在写锁内且**不跨 await**
- [ ] **不新增全局状态**（身份由磁盘内容推导，不引计数器 / epoch / 新全局标志）
- [ ] 写盘仍走既有私有写（tmp + rename + **建文件即 0600**），不得出现 `fs::write` + `chmod`
- [ ] 测试（沙盒临时目录）：模拟「登录先落盘」再让拿旧 baseline 的派生写者去写 → 文件仍是登录写的那份；凭据删除后派生写者不复活它；四行判定表各一条；600 权限在受限写路径上仍然成立
- [ ] `cargo fmt && cargo clippy -q --all-targets -- -W clippy::all` 零警告 + `cargo test` 全绿
