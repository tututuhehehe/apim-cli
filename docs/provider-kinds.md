# 厂商类型：模型 / 非模型

**这是什么**：`kind: model | non_model` 这一个字段在 apim 各处（分页、表单、快捷键、状态口径、探活与
模型列表）产生的全部差异，以及**哪些东西对非模型厂商不成立**。

**为什么不放在 `docs/clients/`**：它讲的是**厂商**类型，不是某个客户端的配置契约 —— 按客户端归类会让
读者去客户端文档里找它。客户端契约见 `docs/clients/codex.md` / `docs/clients/pi.md`；面向用户的部分
（按键、CLI 用法）在 `README.md`。这里只写实现口径与「别踩回去」的约束。

## 数据源只有一个字段

recipe 的 `kind: model | non_model`（`ProviderKind`），**缺省 model**：老 YAML 与内置 recipe 一个字都
不用改；序列化时 model 不写 `kind`（省掉默认值）。

## 类型的唯一入口是创建

- **TUI**：添加表单的「非模型」勾选框（默认跟随当前分页）。
- **CLI**：`apim provider add --kind`（`--kind` **只在 add** 上有）。
- 编辑表单里它**只读**；`save_provider_form` 一律取原值 —— **规则落在保存这一处**，不靠 UI 灰掉。
- `provider set --kind` 与「给非模型厂商传 `--health`」都**报错**（不静默忽略）。
- 要换类型：删了重建，或 `provider copy`。

## 对非模型不成立的东西

非模型厂商**没有模型列表（`m`）、不能导入客户端（`x`）、不探活**（`health` 恒空）。`m` / `x` 在非模型
厂商上**给提示**而不是静默无效（与其它无效位置同一口径：要解释自己）。

**其它一切照旧**：密钥、别名/分组、主页 `⏎`、`c` 复制、`y` 复制厂商、`^Z` 撤销、额度脚本、
`provider ls`、`apim status` —— 都跟类型无关。

## 不适用当前类型的表单行直接不出现

`Field::Toggle` 用 `.hides(下标)` 声明「勾上就把这一行收起来」；勾选状态一变由 Form 自己开关（构造时
先按初值对齐）。隐藏的行：**不渲染、不占弹窗高度、Tab 跳过、也写不进去**（`Field::Text{hidden}`）。
添加与编辑表单的「探活路径」都靠它养活：勾上非模型就**没了这一行**（不是灰掉）。

详情弹窗只列**真适用**的：鉴权 / 探活只服务 HTTP 请求（探活、模型列表），非模型厂商两行都不列；也不列
「类型」那种背景信息（打开它的分页已经说明了一切）。

## 分页状态在 `App` 里

`tab: ProviderKind` + `tabs: [TabView; 2]`：每个分页有自己的 `provider_ids` / `selected` / `filter`，
下标就是 `ProviderKind::ALL` 的顺序。取值一律走 `provider_ids()` / `provider_ids_filtered()` /
`selected_provider()` / `provider_filter()` —— **不要再引入第三个「全局选中项」**。

`rebuild_provider_list` 两个分页各建一份（有密钥的厂商在前，其余按 id 排序）；**保存 / 复制厂商后必须
`focus_provider(id)`**：分页跟着厂商类型跳，否则新建的厂商落在看不见的那一页。

## 快捷键

`Tab` = 切分页（两栏焦点都生效）；`h` / `l` 与 ← / → = 切左右栏焦点。

改按键提示时**四个分支都要过一遍**：

1. 厂商焦点；
2. 模型页密钥焦点；
3. 模型页密钥焦点、且光标在 `AUTH` 行 —— AUTH 行只在内置 `openai` 分页，那支**只留** `x` / `o` / `a` / `r`
   （那行不是密钥，`c` 也不复制任何东西；AUTH 行本身见 AGENTS.md 约定 11）；
4. 非模型页密钥焦点 —— 非模型页**不出现** `m` / `x`。

## 状态口径：非模型看脚本成败

非模型厂商没有探活，所以密钥表状态列与左栏厂商摘要都用**额度脚本的成败**（`ui::script_status`：一处写、
两个地方用）；CLI `status` 同一个口径。

## `health` / `models_url` 保留但不生效

对非模型厂商，这两个字段照旧留在 YAML 里（加载期不拒收），但**不生效**：

- 探活 / 模型列表的消费点一律走 `Recipe::health_call()`（非模型恒为 `None`）与 `is_model()` 门；
- 所以用户手改 `kind:` 也**不会**拿旧 `health` 去发请求（靠的是消费点的门，不是删字段）；
- `auth` 可以省略（`#[serde(default)]`）—— 非模型厂商没有 HTTP 请求。
